Aula 12

Auditoria Híbrida: Performance, Acessibilidade e Usabilidade

Descrição: Esta aula ensina a diferenciar auditoria automatizada de testes manuais, capacitando o aluno a interpretar métricas de Core Web Vitals e WCAG.

Através de dinâmicas práticas e testes de "guerrilha", você aprenderá a identificar falhas que algoritmos não detectam, aplicando as Heurísticas de Nielsen para criar soluções que unem rigor técnico e empatia com o usuário.

01

Acessibilidade e o Padrão WCAG

Acessibilidade e WCAG

Acessibilidade e o Padrão WCAG

A acessibilidade digital, orientada pelas diretrizes WCAG (Web Content Accessibility Guidelines), busca garantir que a web seja inclusiva.

O Google Lighthouse utiliza essas diretrizes (especialmente a versão 2.x nível AA) como referência para avaliar a interface através da engine axe-core.

Auditoria Automática com Lighthouse

O Lighthouse realiza uma varredura no DOM renderizado para identificar violações de código e marcação.

  • Cálculo da Nota: A ferramenta atribui uma pontuação de 0 a 100, baseada em uma média ponderada de auditorias individuais.
  • Critério Binário: Não há crédito parcial; a auditoria para cada item é classificada apenas como "pass" (passou) ou "fail" (falhou).
Auditoria Automática

Erros Óbvios Detectados:

  • Falta de Atributo alt: Verifica se imagens relevantes possuem texto alternativo para descrever seu conteúdo.
  • Baixo Contraste: Analisa se há contraste suficiente entre a cor do texto e o plano de fundo.
  • Falta de Labels: Confere se campos de formulário possuem rótulos associados e se botões ou links têm nomes acessíveis.
  • Erros de Estrutura: Identifica IDS ARIA duplicados e se a hierarquia de cabeçalhos (h1-h6) segue uma lógica coerente.
02

Auditoria Manual: Onde o Humano é Essencial

Auditoria Manual

Embora o Lighthouse seja eficiente, ele cobre apenas um subconjunto de critérios automatizáveis. A validação manual é obrigatória para garantir uma experiência real de uso.

Navegação por Teclado:

  • Funcionalidade: É necessário testar manualmente se o usuário consegue navegar por todos os elementos sem o uso do mouse.
  • Indicadores Visuais: A auditoria manual garante que o fluxo de navegação seja intuitivo e que o usuário identifique onde está na página.
Auditoria Manual

Leitores de Tela:

  • Qualidade do Conteúdo: Uma ferramenta automática pode detectar que um campo tem um rótulo, mas não se o texto é realmente descritivo.
  • Sentido Lógico: Testes de usabilidade com tecnologia assistiva são fundamentais para garantir que o conteúdo lido faça sentido para quem não enxerga, evitando "falsos negativos" onde o código está correto, mas a informação é pobre.
03

Métricas de Interface e UX (Core Web Vitals)

Core Web Vitals

O Lighthouse utiliza o conjunto de métricas Core Web Vitals para avaliar a qualidade da experiência da página, simulando condições de laboratório (rede e CPU limitadas).

Largest Contentful Paint (LCP)

O LCP foca na velocidade de carregamento percebida.

  • O que mede: O tempo necessário para carregar o maior elemento de conteúdo visível na tela (como uma imagem hero, um banner ou um bloco de texto grande).
  • O que afeta negativamente: Imagens muito pesadas, resposta lenta do servidor e recursos (como CSS) que bloqueiam o carregamento do elemento principal.
LCP - Remediação

Estratégias de Remediação LCP:

  • Servir imagens otimizadas em formatos modernos (WebP/AVIF).
  • Usar lazy-loading apenas para conteúdos abaixo da dobra da página.
  • Pré-carregar recursos críticos (como a imagem principal do topo).
Core Web Vitals

Cumulative Layout Shift (CLS)

O CLS avalia a estabilidade visual da interface.

  • O que mede: A soma de todos os deslocamentos inesperados de layout enquanto a página carrega.
  • O que causa frustração: Elementos que "pulam" de posição (devido a anúncios injetados ou imagens sem tamanho definido), fazendo o usuário clicar no lugar errado.
CLS - Remediação

Estratégias de Remediação CLS:

  • Sempre definir largura (width) e altura (height) ou a proporção (aspect-ratio) em imagens e iframes.
  • Reservar espaço prévio para componentes dinâmicos, como banners e widgets.
  • Evitar a inserção de novos conteúdos acima de elementos que já foram carregados.
Diagnóstico e Priorização

Diagnóstico e Priorização

Para melhorar essas métricas, o relatório do Lighthouse oferece seções específicas de remediação:

  • Opportunities (Oportunidades): Lista sugestões técnicas ordenadas pelo impacto estimado no tempo de carregamento (ex: compressão de texto, otimização de bundles de JavaScript).
  • Diagnostics (Diagnósticos): Detalha o comportamento da página, como o tamanho do DOM e o trabalho excessivo na main thread (fio principal de execução).

Regra de Ouro: Deve-se priorizar primeiro as correções que influenciam diretamente o LCP e o TBT (Total Blocking Time), seguidas pela estabilidade visual do CLS.

Embora o Lighthouse forneça dados valiosos em ambiente de desenvolvimento (laboratório), os especialistas recomendam combiná-lo com o RUM (Real User Monitoring) para monitorar como os usuários reais experimentam o site em produção.

04

Fundamentos e Prática da Usabilidade

Usabilidade

A usabilidade não é apenas um "sentimento", mas uma metodologia rigorosa de observação para descobrir problemas e oportunidades em interfaces. Mesmo os melhores designers não conseguem prever todas as variáveis do cérebro humano sem testar com usuários reais.

Usabilidade

Os 5 Componentes da Usabilidade (Nielsen)

Para medir a facilidade de uso de uma interface, analisamos cinco pilares fundamentais:

  • Aprendizagem (Learnability): Quão fácil é para os usuários realizarem tarefas básicas na primeira vez que encontram o design?
  • Eficiência (Efficiency): Uma vez que os usuários aprenderam o design, quão rápido eles podem realizar as tarefas?
  • Memorização (Memorability): Quando os usuários retornam ao design após um período sem usá-lo, com que facilidade eles podem restabelecer a proficiência?
  • Erros (Errors): Quantos erros os usuários cometem, quão graves são esses erros e com que facilidade eles podem se recuperar deles?
  • Satisfação (Satisfaction): Quão agradável é usar o design?
Usabilidade

Testes de Usabilidade: Identificando Problemas e Oportunidades

O teste de usabilidade é a ferramenta prática para aplicar os conceitos acima. Ele se baseia em três elementos centrais:

Elemento Papel na Usabilidade
Facilitador Orienta o participante, fornece instruções e garante dados de alta qualidade sem influenciar o comportamento.
Tarefas Atividades realistas que o usuário realizaria na vida real. A redação precisa é crucial para evitar o priming (influência acidental).
Participante Um usuário realista do produto (ou com perfil semelhante) que executa as tarefas e fornece feedback.
Métodos de Usabilidade

O Método "Pensar em Voz Alta"

Para entender a Memorização e a Aprendizagem, utilizamos a técnica de pedir que o participante narre seus pensamentos enquanto navega. Isso revela as motivações e os obstáculos mentais que métricas puras não mostram.

Heurísticas de Nielsen: O Mapa Mental de Design

Enquanto o teste de usabilidade observa o comportamento, as heurísticas funcionam como um guia preventivo para o designer. Exemplos práticos:

  • Prevenção de Erros: Redigir tarefas claras e interfaces intuitivas para evitar que o usuário se perca.
  • Feedback do Sistema: Como visto na montagem de um teste, o facilitador observa se o sistema responde às ações do usuário em tempo real.

Performance como UX: Core Web Vitals: A experiência do usuário é diretamente afetada pela performance técnica. O atraso no carregamento e a instabilidade visual impactam dois componentes de Nielsen: Eficiência (LCP) e Satisfação (CLS).

05

Dinâmica Prática: "O Ciclo de Auditoria"

Atividade 1

Atividade 1: Auditoria Cega com Lighthouse

Descrição: Para esta primeira parte, vamos focar exclusivamente na Auditoria Técnica de Acessibilidade utilizando o Google Lighthouse. O objetivo é fazer com que vocês compreendam que a acessibilidade começa no código e na estrutura semântica da página.

Objetivo: Identificar barreiras críticas de acessibilidade digital e entender como algoritmos de varredura interpretam uma interface.

1. Preparação

  • Ferramenta: Navegador Google Chrome (Desktop).
  • Objeto de Estudo: Escolham um site de alta complexidade (ex: um portal de notícias, uma loja virtual famosa ou o site de uma prefeitura).
Atividade 1

2. Execução do Diagnóstico (Passo a Passo)

  1. Abra o site escolhido e acesse o Inspetor de Elementos (F12 ou botão direito > Inspecionar).
  2. Vá até a aba Lighthouse.
  3. Em "Categories", selecione "Performance" e "Accessibility".
  4. Em "Device", escolha "Desktop" (para facilitar a visualização inicial).
  5. Clique em "Analyze page load".
Atividade 1

3. Análise dos Resultados

Após a geração do relatório, vocês devem criar, preencher e entregar um "Checklist de Impacto" baseado nos achados:

  • A Pontuação: Qual foi a nota de 0 a 100? (Lembre-os de que o critério é binário: ou passa, ou falha).
  • Os "Vilões" do Código: Identifique e descreva pelo menos um erro em cada uma destas categorias comuns apontadas pela ferramenta:
    • Contraste: Onde o texto está difícil de ler contra o fundo?
    • Nomes e Rótulos: Existem botões ou links que o Lighthouse diz estarem "vazios" (sem texto interno ou aria-label)?
    • Atributos alt: Liste imagens que não possuem descrição alternativa.
    • Hierarquia: Os títulos (h1, h2, h3) estão em ordem lógica ou pulando níveis?
Atividade 1

4. Desafio de Reflexão: "O Falso Positivo"

Encontrem um elemento que o Lighthouse deu como "Pass" (Aprovado), mas que, ao olharem visualmente, parece estar errado ou confuso.

Exemplo: Uma imagem que tem um alt="foto". Para o Lighthouse, o atributo existe (Pass), mas para um usuário de leitor de tela, a descrição é inútil.

Atividade 2

Atividade 2: O Teste de Guerrilha (Humano vs. Máquina)

Objetivo: Identificar problemas de usabilidade que o código não revela e validar as 5 metas de usabilidade de Nielsen (Aprendizado, Eficiência, Memorização, Erros e Satisfação).

1. Preparação das Duplas

  • O Usuário: Deve tentar realizar a tarefa como se estivesse sozinho em casa.
  • O Observador: Não pode ajudar, não pode dar dicas e não pode explicar como o site funciona. Ele deve apenas anotar e observar.

2. A Missão (Definição da Tarefa)

O Observador deve definir uma tarefa clara e objetiva no site analisado na Etapa 1. Exemplos:

  • "Encontre um tênis de corrida azul, número 40, abaixo de R$ 300,00 e chegue até a tela de pagamento."
  • "Descubra como solicitar a segunda via do IPTU neste portal da prefeitura."
Atividade 2

3. Execução: O Método "Think Aloud" (Pensar em Voz Alta)

Peça para o Usuário narrar seus pensamentos enquanto navega:

"Estou procurando o menu, mas esse banner está me atrapalhando..."

"Achei que esse ícone era para o carrinho, mas ele abriu o chat..."

"Onde eu clico para confirmar? O botão sumiu?"

4. O que o Observador deve anotar (Grade de Observação)

  • Hesitação: Onde o usuário parou por mais de 3 segundos sem saber o que fazer?
  • Caminho em Falso: Onde o usuário clicou achando que era uma coisa, mas era outra?
  • Frustração (Satisfação): Em que momento o usuário suspirou, reclamou ou pareceu irritado?
  • Métrica de Erro: Quantas vezes o usuário tentou realizar uma ação e falhou (ex: clicou em um texto que não era link)?
Atividade 2

5. O Confronto: Lighthouse vs. Realidade

Após o teste (que deve durar cerca de 10 a 15 minutos), a dupla deve sentar e comparar as notas:

  1. O Silêncio do Robô: Algum problema de usabilidade irritou o usuário, mas o Lighthouse deu "nota 100"? (Ex: O layout é confuso, mas o código está tecnicamente correto).
  2. O Peso do Core Web Vitals: O Lighthouse acusou um LCP (carregamento) baixo. O usuário percebeu isso? Ele comentou que o site estava "lento" ou "travado"?
  3. Acessibilidade Vivida: Se o Lighthouse apontou falta de contraste, o usuário teve dificuldade real de ler alguma informação?

6. Conclusão da Etapa

Cada dupla deve resumir sua experiência em uma frase:

"O Lighthouse disse que o site era [Nota], mas nosso usuário [conseguiu/não conseguiu] completar a tarefa porque [motivo de usabilidade]."

Etapa 3

Etapa 3: Remediação

Vocês devem propor correções para os problemas encontrados:

  1. Corrigir um erro de contraste.
  2. Adicionar um aria-label.
  3. Redesenhar um fluxo que causou confusão no teste de guerrilha.

Para fechar o ciclo da atividade, a Etapa 3: Relatório de Diagnóstico e Plano de Remediação servirá como o documento final que consolida a visão técnica e a visão humana sobre o produto analisado.

Atividade Final

Atividade Final: O Plano de Remediação

Objetivo: Consolidar os dados das etapas anteriores (Lighthouse + Teste de Guerrilha) e propor soluções práticas baseadas nos pilares de performance, acessibilidade e usabilidade.

1. Estrutura do Documento de Entrega

A dupla deve entregar um relatório em formato de PDF contendo os seguintes tópicos:

A. O Cenário Atual (Raio-X)

  • Screenshot do Lighthouse: Exibir a nota de Acessibilidade e as métricas de Core Web Vitals (LCP e CLS).
  • A "Dor" do Usuário: Descrição breve da maior dificuldade encontrada pelo parceiro durante o teste de guerrilha.
Atividade Final

B. Tabela de Achados e Soluções (O Coração do Trabalho)

Vocês devem preencher uma tabela comparativa com pelo menos 3 problemas críticos.

Problema Identificado Origem (Lighthouse ou Usuário?) Impacto (Baixo, Médio ou Crítico) Proposta de Solução (Remediação)
Ex: Botão sem nome Lighthouse Crítico Inserir atributo aria-label no HTML.
Ex: Menu confuso Usuário Médio Reorganizar categorias por ordem alfabética.
Ex: Layout "pulando" Lighthouse (CLS) Baixo Definir largura e altura fixa para as imagens.
Atividade Final

C. Justificativa Baseada em Nielsen

Escolha um dos problemas de usabilidade detectados e explique qual das 10 Heurísticas de Nielsen ou qual dos 5 componentes de usabilidade ele fere.

Exemplo: "A falha na busca fere a Eficiência, pois o usuário precisou de 10 cliques para algo que deveria ser feito em 2."

2. Conclusão Crítica: "A Ponte"

A dupla deve responder, em um parágrafo, à seguinte questão:

"Se corrigíssemos apenas o que o Lighthouse (robô) apontou, a experiência do nosso usuário seria 100% satisfatória? Porquê?"

Avaliação

3. Critérios de Avaliação

  • Consistência: Os problemas citados na entrega final condizem com o que foi observado nas etapas anteriores?
  • Qualidade Técnica: A solução proposta para o erro do Lighthouse faz sentido técnico (ex: citar atributos alt, labels, contraste)?
  • Empatia de Design: O aluno conseguiu identificar a frustração do colega e traduzir isso em uma melhoria de interface?
